# OPS Job 平台缺口修复设计

## 目标

按优先级修复当前平台中“后端已有但前端不可达”、敏感配置回显、主机分组交互缺失、流程/调度认知不清、流程列表全量加载以及前端测试边界混乱等问题。

## 约束与架构边界

- 流水线执行节点只包含脚本执行、文件传输、作业执行方案。
- 人工确认、条件分支、并行、汇聚、子流程属于流程引擎控制节点，不进入 Agent 执行服务。
- 保留当前作业平台与运维台的双壳层，不做整体导航重构。
- 保留用户现有未提交修改，不执行 reset、restore 或强制覆盖。
- 不把敏感凭据原文发送到列表展示或普通编辑表单。

## 任务一：可达性与敏感配置

1. 为现有权限查询页接入路由和菜单。
2. 增加最小可用的用户管理入口，复用已有 `/auth/users/` API；用户资料编辑能力与后端 serializer 保持一致。
3. 系统配置列表对 Secret 类配置只展示配置状态，不展示原文；编辑时使用密码输入并支持保留原值。
4. 添加针对路由、敏感配置展示和用户页面的前端测试。

## 任务二：交互和领域边界

1. 实现主机分组右键菜单，复用已有三点菜单动作，保证只读状态不出现写操作。
2. 流程节点库按“执行动作”和“流程控制”分组，并加上边界说明。
3. 明确执行方案定时任务与流水线定时调度的 UI 文案，避免两个“定时任务”概念混用。
4. 添加组件级契约测试，确认控制节点仍由流程引擎处理。

## 任务三：数据加载与测试边界

1. 流程模板列表使用后端分页参数，避免每次加载全部运行记录。
2. 将 Vitest 的测试范围限制在 `src`，避免误收集 Playwright 的 `e2e` 测试。
3. 保留单测、类型检查、生产构建和 Playwright 测试的独立执行入口。

## 验收标准

- 权限页面和用户页面可以从菜单进入，路由刷新后仍可访问。
- Secret 列表不显示明文，编辑空值不会意外清空已有凭据。
- 分组右键菜单可完成编辑、添加子分组、测试连接和删除。
- 流程节点库明确区分执行节点与流程控制节点。
- 流程列表请求包含分页信息，`pnpm test` 不再收集 `e2e` 文件。
- `pnpm type-check`、`pnpm build`、`pnpm test` 通过；Playwright 单独运行并记录环境边界。
